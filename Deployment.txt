1. OVERVIEW & CLOUD ARCHITECTURE
================================================================================

To run a full-stack Spring Boot web application with a live database 100% free,
we used the following 3-tier cloud architecture:

1. Code Hosting:
   - Platform: GitHub
   - Purpose: Stores project code, tracks versions, triggers automatic builds.

2. Cloud Database:
   - Platform: TiDB Cloud Serverless (MySQL Compatible)
   - Cost: Free ($0/month forever, 5 GB storage, no credit card required)
   - Purpose: Replaces local laptop MySQL (localhost:3306) with a 24/7 cloud DB.

3. Cloud Application Server:
   - Platform: Render.com
   - Cost: Free ($0/month)
   - Purpose: Automatically compiles code, runs Spring Boot, and serves the website.

4. STEP 3: MAKING THE PROJECT CLOUD-READY (CODE ADJUSTMENTS)
================================================================================

WHAT WAS CHANGED & WHY:

1. Unified Frontend into Spring Boot:
   - What: Copied frontend HTML/JS files into "backend/src/main/resources/static/".
   - Why: Allows Spring Boot to serve both the web pages and the REST APIs
     from the exact same domain. This avoids CORS errors and eliminates the need
     to pay for or manage two separate hosting services.

2. Dynamic API URLs (myscript.js & register.html):
   - What: Updated fetch calls to automatically use:
     - "http://localhost:8080" when running locally (Live Server on port 5500).
     - Relative URLs ("/courses", "/courses/register") when deployed in cloud.
   - Why: Code works seamlessly in both local development and live production
     without needing manual edits.

3. Cloud Port Binding (application.properties):
   - What: Added "server.port=${PORT:8080}".
   - Why: Render dynamically assigns its own port number at startup. This setting
     ensures Spring Boot listens on whatever port Render gives it.

4. Default Course Seeder (CourseRegistrationSystemApplication.java):
   - What: Added CommandLineRunner to insert 3 starter courses:
     - CS101: Java Essentials (John Doe, 6 weeks)
     - CS102: Python for ML (Jane Smith, 8 weeks)
     - CS103: Spring Boot (Alex Brown, 4 weeks)
   - Why: So the course table is populated immediately upon first deployment
     instead of showing an empty blank page.

5. Multi-Stage Dockerfile:
   - What: Created "Dockerfile" at project root with Java 21 and Maven.
   - Why: Tells Render exactly how to build the jar and start the container
     with 1-click.

6. STEP 5: TROUBLESHOOTING & FIXING DEPLOYMENT ERRORS
================================================================================

ERROR 1: Hibernate Dialect Failure
- Log Error: "Unable to determine Dialect without JDBC metadata"
- Reason: Hibernate tried to guess which SQL language to use before the cloud
  SSL handshake completed.
- Fix: Explicitly set in application.properties:
  spring.jpa.database-platform=org.hibernate.dialect.MySQLDialect
  spring.jpa.properties.hibernate.dialect=org.hibernate.dialect.MySQLDialect

ERROR 2: Database Access Denied (Typo in Credentials)
- Log Error: "Access denied. Please check your user name and password."
- Reason: When reading text from screenshots, certain characters look identical:
  - The first letter of the password was a lowercase "l" (L), not the digit "1".
  - The username had uppercase "WE" ("cRYfvuWEgevuBis.root").
- Fix:
  - You pasted the exact text from the TiDB Cloud console.
  - We verified the credentials directly using a Python script (100% success).
  - Updated application.properties with the verified username, password, and
    "sslMode=REQUIRED".
  - Pushed commit to GitHub. Render automatically redeployed.

spring.jpa.properties.hibernate.dialect=org.hibernate.dialect.MySQLDialect
